# Xrayebator v0.5.0 — сервер получил панель управления

> Первый общий релиз обновлённого серверного менеджера и активного Electron-приложения. Релиз публикуется из `howdeploy/Xrayebator/main`.

## Если объяснить в двух словах

Xrayebator раньше в основном требовал работы через терминал. В `v0.5.0` появился отдельный графический пульт: сервер по-прежнему настраивается и работает на VPS, а **Xrayebator Desktop GUI** подключается к нему по SSH и вызывает те же проверенные серверные команды.

```text
┌──────────────────────────────┐
│  Xrayebator Desktop GUI      │
│  Windows · macOS · Linux     │
│  Dashboard · QR · settings   │
└──────────────┬───────────────┘
               │ SSH + documented CLI
               ▼
┌──────────────────────────────┐
│  Xrayebator на VPS           │
│  Bash · Xray Reality · HAPP  │
│  profiles · backup · rollback │
└──────────────┬───────────────┘
               │ HTTPS subscription
               ▼
        HAPP / v2rayNG / v2rayN
```

Главное: GUI не является вторым VPN-движком. Источником истины остаётся серверный `xrayebator`, а графическая панель делает его ежедневное обслуживание понятнее.

## Что появилось

### Xrayebator Desktop GUI

- Dashboard со списком VPS, состоянием доступности и метаданными сервера.
- Мастер добавления VPS: SSH-доступ, установка, quickstart и получение subscription URL.
- Страница ключей: обновление подписки, копирование URL, VLESS-ссылок и QR-кодов.
- Настройки сервера: список профилей, создание и удаление профилей.
- Смена fingerprint, SNI и порта без ручного редактирования `config.json`.
- Выбор языка интерфейса: русский, English и 简体中文.
- Поддержка прямого root-доступа или sudo, пароля или SSH-ключа.

### Сервер и подписка

- Стандартный HAPP-профиль использует schema v3 и семь маршрутов:
  `xhttp-legacy`, `xhttp-pq`, `tcp-mux`, `grpc`, `tcp-vision`, `tcp-utls-firefox` и `tcp-xudp`.
- В обычную HAPP-выдачу попадают шесть подходящих маршрутов, а полный профиль сохраняется на сервере.
- Появились отдельные CLI-операции для GUI: `profiles`, `profile-create`, `profile-delete`, `fp-change`, `sni-change`, `sni-list` и `port-change`.
- Маршруты и профили синхронизируются после изменений inbound-настроек.
- Добавлены или расширены bypass, cascade, self-steal и post-quantum XHTTP сценарии в серверном меню.

### Установка и обслуживание

- Установщик получил безопасное управление шагами: `--check`, `--resume` и `--fresh`.
- Xray-core проверяется по SHA-256 перед установкой.
- Улучшены IPv6-сценарии установщика, DNS fallback и форматирование IPv6 URL. Для публичной IP-TLS подписки всё ещё нужен IPv4; IPv6-only VPS использует доменный TLS-режим с достижимой A/AAAA-записью.
- Обновлены миграции старых установок, включая очистку устаревших проектных настроек.
- Удаление сервера чистит созданные Xrayebator сервисы, профили, сертификаты и принадлежащие проекту UFW-правила.

## Что стало надёжнее

Изменение конфигурации теперь мыслится как операция с запасным выходом:

```text
backup
  │
  ▼
изменить config.json и профиль
  │
  ▼
проверить конфиг через Xray
  │
  ├── всё хорошо ──► перезапустить сервис
  │
  └── ошибка ───────► откатить конфиг из backup
```

В проекте появились проверки транзакций, миграций, firewall, VLESS-ссылок, SNI/port-change и HAPP-пути. Для Bash добавлена полная validation-suite из 24 скриптов, а для Electron GUI — unit-тесты для SSH, JSON-ответов, подписки, портов и shell-команд.

## Сборка для трёх систем

Релизный workflow `.github/workflows/release.yml` сначала запускает Electron typecheck и unit-тесты на Ubuntu, а затем собирает приложение нативно для:

- Windows — установщик NSIS;
- macOS Apple Silicon — DMG;
- Linux — AppImage.

Релиз публикует AppImage как Linux-пакет. Snap не собирается: workflow явно ограничивает Linux target до AppImage, поэтому пользователю не предлагается неподготовленный второй формат.

Сборка каждой платформы выполняется на соответствующем runner. Windows-локальная среда не является источником истины для POSIX-теста, использующего `/bin/sh`; authoritative-проверка выполняется на Linux CI.

## Важно перед обновлением

### Breaking changes

- Активным десктоп-приложением теперь считается Electron + React + TypeScript в `src/`.
- Старый PySide6-клиент перенесён в `gui-legacy/` и сохранён как архивный отдельный проект.
- Electron GUI не отображает весь интерактивный серверный menu surface.

### Что GUI пока не делает

Следующие возможности остаются в терминальном `xrayebator`:

- `bypass`;
- `probe-test`;
- revoke подписки;
- `happ-setup`;
- cascade;
- self-steal;
- просмотр service logs/status;
- полный интерактивный терминальный меню.

### Честные ограничения

- SSH-пароли, sudo-пароли и passphrase ключей не сохраняются, но subscription URL и полученные VLESS-ссылки являются bearer credentials и хранятся локально для работы панели. Защитите данные приложения и отзывайте подписку при утечке.
- `quickstart` и `happ-setup` имеют разные области ответственности; после lifecycle update нужно проверить Xray, DNS и subscription endpoint.
- Полноценного end-to-end теста упакованного Electron-приложения пока нет.
- Последующий аудит обнаружил отдельные hardening-задачи в `safe_jq_write`, lifecycle rollback, JSON escaping и проверках существующих inbound. Они не заявляются исправленными в `v0.5.0`.

## Как обновиться

### Сервер

Для обычного обновления менеджера с выбранной ветки:

```bash
sudo xrayebator update main
```

Для полного lifecycle-обновления используется отдельная команда:

```bash
sudo xrayebator-update main
```

Эти команды не являются синонимами. После обновления проверьте состояние Xray, DNS и ссылку подписки.

### Xrayebator Desktop GUI

1. Скачайте пакет для своей ОС из GitHub Release.
2. Установите его поверх предыдущей версии.
3. Откройте сохранённую карточку VPS или добавьте сервер заново.
4. После обновления сервера обновите подписку в клиенте и переподключитесь.

## Проверки релиза

Перед публикацией должны пройти:

```bash
npm run typecheck
npm test
npm run build
bash -n xrayebator install.sh update.sh uninstall.sh
```

Полная Bash validation-suite запускается в Ubuntu CI. GitHub Release считается готовым только после успешной сборки Windows, macOS и Linux.
