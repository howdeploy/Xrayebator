# Xrayebator 0.7.5-beta.1 -- WARP egress, full AWG 3.1 transport protection, private cascade

**Date:** 2026-11-13
**Previous release:** `0.7.3` (2026-11-07)
**Xray-core:** `26.10.31` (unchanged)
**Status:** beta. For production stay on `0.7.3`.

This cut answers a real change in how connections get blocked. Since 3 November the censor has
been scoring traffic with neural networks rather than matching static signatures, and the practical
effect is that a working server can stop working within hours while its configuration never changed.
The block is no longer aimed at the protocol: it collects behaviour across a session -- packet sizes
and their order, handshake timings, keepalive cadence, traffic volume, connection counts -- and then
probes the endpoint directly.

What that means concretely. Russian applications on the client device report the address they observe
as the external one, and destinations get pinged from the outside to confirm a server is live and
speaks a tunnel. An address that answers those probes and is also the address clients connect to is
enough to burn it, and the observation then widens to the surrounding subnet. Rotating the IP alone
buys hours to days, which is why this release attacks the problem from three sides instead of one.

The headline: the server can now have an egress address that differs from its ingress, and
AmneziaWG 3.1 emits the whole transport-protection group instead of half of it.

## What was wrong

### 1. Traffic left from the ingress address

Russian applications collect the external address they see and report it, and the censor then
confirms it by probing from the outside. When the egress address equals the ingress address, that
single observation is enough to burn it, and the subnet goes under watch next. We had no
`sendThrough` at all, and the catch-all went to `direct` -- so the egress address was exactly the
address clients connect to.

### 2. "AWG 3.1" was only half enabled

The mode was called 3.1 but emitted only `HeaderProtectionKey` and `RandomTrailers`. Per the
AmneziaWG documentation transport protection in 3.x also covers `ContentPaddingAddition` and timer
randomisation. Without them, repeated packet sizes and constant intervals remain exactly what
behavioural DPI scores.

### 3. An identical junk train for every client

`Jc`, `Jmin` and `Jmax` were server-wide constants (5 / 10 / 50), so every client started its
session the same way. The AmneziaWG documentation calls that a ready-made DPI pattern.

### 4. A defect in the 3.1 upgrade path

`_awg_ensure_31_params` returned early when `S3`, `S4` and `HeaderProtectionKey` were already
present. An installation that had received the early 3.1 subset stayed without transport protection
forever -- no path would ever upgrade it.

### 5. The server country was not detected without quickstart

`_geo_detect_country` was called only from `quickstart` and `happ-setup`, and the marker file is
written only there. A server installed with `install.sh` and profiles created over the CLI never had
that marker, so `inspect --json` returned empty `country`/`city`/`flag` and the desktop app showed
the server without a country flag.

### 6. A leak in our own change

The first WARP version passed the private key to `jq` via `--arg`, putting it into
`/proc/<pid>/cmdline` (`0444`, readable by any local user). Same class of leak that 0.7.3 closed.

## What changed

### Egress: Cloudflare WARP

Three commands, available from both the CLI and the desktop app.

```bash
sudo xrayebator warp-setup              # register a device, keys 0600
sudo xrayebator warp-mode games-direct  # games direct, everything else via WARP
sudo xrayebator warp-status             # JSON: configured / mode / applied
```

Three modes:

| Mode | Behaviour |
|---|---|
| `all` | all traffic through WARP |
| `games-direct` | `geosite:category-games` direct, everything else through WARP |
| `off` | catch-all returns to `direct` |

Why WARP rather than a second IP from the hoster: a second address usually arrives in the same
subnet, so it is burned together with the first and has to be paid for again. WARP is free, needs no
second server as a gateway and no second IP.

Two details that matter in practice: `reserved` (three bytes from registration) is mandatory -- WARP
does not answer without it; and `MTU` stays at 1280.

Honest limits, measured on a live host:

* latency grows by roughly 30-40 ms against targets outside Cloudflare's network;
* throughput stays within 60-100% of the direct path depending on the far side and the hour;
* WARP is intermittently unreachable for tens of seconds and recovers on its own. That is exactly
  why the default for gaming is `games-direct` rather than `all`.

### AmneziaWG 3.1: the full transport group

The whole set is emitted now, not only header encryption:

| Key | What it removes |
|---|---|
| `HeaderProtectionKey` | plaintext header type bytes |
| `RandomTrailers = on` | fixed handshake packet lengths |
| `ContentPaddingAddition` (2..10) | repeated transport packet sizes |
| `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts` | constant session timings |

`Jc`, `Jmin` and `Jmax` became client-side and unique per profile: values are derived
deterministically from the profile name and its public key, so they are stable across calls and need
no stored state. `S1`-`S4`, `H1`-`H4` and `HeaderProtectionKey` must still match the server -- they
were left alone, so already issued `.conf` files keep working.

### Private cascade (opt-in)

`private-cascade render` generates a separate config for a Russian ingress with a foreign exit: some
destinations go out locally, the rest through a restricted foreign node. The live configuration is
not modified, and the result is validated by the installed core before it is written. Deployment is
documented separately and needs two servers.

### Desktop

WARP now appears in "Security and TLS": state, mode via three buttons, MTU and endpoint. The desktop
calls exactly the same commands as SSH -- it has no registration logic of its own.

### Fixes

* The server country and flag resolve without `quickstart`: when the marker is absent `inspect`
  performs a network lookup and writes nothing, so the read-only contract is preserved.
* The WARP private key reaches `jq` through the environment, never as an argument.
* `test-ssh-protect.sh` no longer inherits the live session's `SSH_CONNECTION`/`SSH_CLIENT`:
  previously the fallback branch compared against the real connection address, which made the check
  silently vacuous on a real host.

## Verified live

One host, Ubuntu 22.04, Xray 26.11.9, AmneziaWG tools 3.1.

| What | Result |
|---|---|
| Egress address substitution | ingress and egress differ, `warp=on` |
| `games-direct` mode | applied, config valid, service active |
| `geosite:category-games` | present (1063 domains); game domains go direct, control domains are blocked |
| AWG 3.1 keys | the kernel accepted `content padding addition`, `rekey after time` and the rest, and reads them back unchanged |
| Xray routes | 6 transports plus PQ, all HTTP 200, 171-310 ms |
| Hysteria 2 | real traffic through the tunnel, HTTP 200 |
| Full `validation/` | **51/51** |
| Country status | `Germany` / `Frankfurt am Main` / flag, marker not created |

Separately confirmed that the cascade does not touch the live config, and that `warp-mode` takes a
backup and rolls back when the core refuses the candidate.

## Upgrading

```bash
sudo xrayebator-update dev
```

Compatibility is unchanged: the server-side `--token` and `--aws-secret-access-key` options are
still there, so an old desktop works with a new server and vice versa. This release adds no
migrations and requires no server configuration change.

**One check after upgrading**, if the server predates the transport group:

```bash
sudo xrayebator awg-31 --on     # fills in the missing keys
awg show awg0                   # content padding addition and rekey should appear
```

If `awg show` prints `random trailers: off` and no padding, the server is running a manager binary
older than this release -- update it and repeat the command.

## Known limitations

* The `all` mode adds 30-40 ms; use `games-direct` for interactive games.
* WARP is somebody else's infrastructure: Cloudflare sees that traffic, the service is free but rate
  limited, and registration can be refused from a heavily used address.
* Fail-closed for WARP is not implemented yet: when WARP is unreachable traffic does not leak to
  `direct`, but it does not work either.
* The private cascade needs two servers and Python 3 on the ingress node.
