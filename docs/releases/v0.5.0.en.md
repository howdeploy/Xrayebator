# Xrayebator v0.5.0 — the server gets a control panel

> The first combined release of the updated server manager and the active Electron application. The release is published from `howdeploy/Xrayebator/main`.

## In two words

Xrayebator used to be primarily a terminal tool. In `v0.5.0`, it gains a dedicated graphical control panel: the server is still configured and runs on the VPS, while **Xrayebator Desktop GUI** connects over SSH and invokes the same verified server commands.

```text
┌──────────────────────────────┐
│  Xrayebator Desktop GUI      │
│  Windows · macOS · Linux     │
│  Dashboard · QR · settings   │
└──────────────┬───────────────┘
               │ SSH + documented CLI
               ▼
┌──────────────────────────────┐
│  Xrayebator on the VPS       │
│  Bash · Xray Reality · HAPP  │
│  profiles · backup · rollback │
└──────────────┬───────────────┘
               │ HTTPS subscription
               ▼
        HAPP / v2rayNG / v2rayN
```

The key point: the GUI is not a second VPN engine. The server-side `xrayebator` remains the source of truth, while the graphical panel makes everyday administration easier to understand.

## What was added

### Xrayebator Desktop GUI

- Dashboard with VPS cards, reachability status, and server metadata.
- VPS add wizard: SSH access, installation, quickstart, and subscription URL retrieval.
- Keys page: subscription refresh, URL copying, VLESS links, and QR codes.
- Server Settings: list, create, and delete profiles.
- Change fingerprint, SNI, and port without manually editing `config.json`.
- Interface languages: Russian, English, and Simplified Chinese.
- Direct root or sudo access, using either a password or an SSH key.

### Server and subscription

- The standard HAPP profile uses schema v3 and seven routes:
  `xhttp-legacy`, `xhttp-pq`, `tcp-mux`, `grpc`, `tcp-vision`, `tcp-utls-firefox`, and `tcp-xudp`.
- The regular HAPP output publishes six suitable routes, while the complete profile remains on the server.
- New CLI operations for the GUI: `profiles`, `profile-create`, `profile-delete`, `fp-change`, `sni-change`, `sni-list`, and `port-change`.
- Routes and profiles are synchronized after inbound-level changes.
- Bypass, cascade, self-steal, and post-quantum XHTTP scenarios are available in the server menu.

### Installation and maintenance

- The installer supports safe step control with `--check`, `--resume`, and `--fresh`.
- Xray-core is verified with SHA-256 before installation.
- IPv6-only VPS scenarios and the related DNS/URL handling are improved.
- Migrations for older installations have been updated, including cleanup of obsolete project settings.
- Uninstall removes Xrayebator services, profiles, certificates, and project-owned UFW rules it created.

## What became more reliable

Configuration changes now follow an operation with a way back:

```text
backup
  │
  ▼
edit config.json and profile
  │
  ▼
validate the config with Xray
  │
  ├── success ──► restart the service
  │
  └── error ────► restore the config from backup
```

The project includes checks for transactions, migrations, firewall behavior, VLESS links, SNI/port-change, and the HAPP path. The Bash side has a 24-script validation suite, while the Electron GUI has unit tests for SSH, JSON responses, subscriptions, ports, and shell commands.

## Builds for three platforms

The `.github/workflows/release.yml` workflow runs Electron typecheck and unit tests on Ubuntu, then builds native packages for:

- Windows: `Xrayebator-0.5.0-win.exe` (NSIS installer);
- macOS Apple Silicon: `Xrayebator-0.5.0-mac-arm64.dmg` and `Xrayebator-0.5.0-mac-arm64.zip` (the ZIP is required by the built-in updater);
- Linux: `Xrayebator-0.5.0-linux.AppImage`.

`AppImage` is a portable Linux package: download it, make it executable with `chmod +x`, and run it without installing through `apt`. Snap is not built; the workflow explicitly limits the Linux target to AppImage so users are not offered an unprepared second format.

Each platform is built on its corresponding runner. A native Windows environment is not the source of truth for the POSIX `/bin/sh` test; the authoritative check runs on Linux CI.

## Important before upgrading

### Breaking changes

- The active desktop application is now the Electron + React + TypeScript implementation in `src/`.
- The old PySide6 client has moved to `gui-legacy/` and remains a separate archival project.
- The Electron GUI does not expose the entire interactive server menu.

### What the GUI does not do yet

The following capabilities remain in the terminal `xrayebator`:

- `bypass`;
- `probe-test`;
- subscription revoke;
- `happ-setup`;
- cascade;
- self-steal;
- service logs/status;
- the full interactive terminal menu.

### Honest limitations

- SSH passwords, sudo passwords, and key passphrases are not persisted, but the subscription URL and fetched VLESS links are bearer credentials stored locally for the panel to work. Protect the application data and revoke the subscription after a leak.
- `quickstart` and `happ-setup` have different responsibilities; after a lifecycle update, check Xray, DNS, and the subscription endpoint.
- There is no full end-to-end test of the packaged Electron application yet.
- A later audit found hardening tasks around `safe_jq_write`, lifecycle rollback, JSON escaping, and existing-inbound validation. This release does not claim to fix them.

## How to upgrade

### Server

For a normal manager update from a selected branch:

```bash
sudo xrayebator update main
```

For a full lifecycle update:

```bash
sudo xrayebator-update main
```

These commands are not synonyms. After the update, check Xray, DNS, and the subscription URL.

### Xrayebator Desktop GUI

1. Download the package for your operating system from the GitHub Release.
2. Install it over the previous version.
3. Open the saved VPS card or add the server again.
4. After updating the server, refresh the subscription in the client and reconnect.

## Release checks

The following checks must pass before publication:

```bash
npm run typecheck
npm test
npm run build
bash -n xrayebator install.sh update.sh uninstall.sh
```

The complete Bash validation suite runs in Ubuntu CI. The GitHub Release is considered ready only after Windows, macOS, and Linux builds succeed.
