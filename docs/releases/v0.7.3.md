# Xrayebator 0.7.3 -- секреты вне аргументов процессов, починка snap-certbot и самовосстановление Hysteria

**Дата:** 2026-11-07
**Предыдущий релиз:** `0.7.2` (2026-11-04)
**Xray-core:** `26.10.31` (без изменений)

Патч-релиз по итогам трёх живых прогонов подряд: Debian 13, Ubuntu 24.04 и Ubuntu 22.04.
Главное -- закрыта утечка секретов через командную строку процессов и починены два дефекта,
которые ломали работу на реальных серверах (свежий Ubuntu 24.04 и повреждённый бэкенд).

## Что было не так

### 1. Токены в аргументах процессов (безопасность)

`/proc/<pid>/cmdline` читается **любым** пользователем хоста (`0444`), а
`/proc/<pid>/environ` -- только владельцем процесса и root (`0400`). До этого релиза
три группы кредов ходили именно аргументами, то есть были видны любому локальному
аккаунту -- включая служебного пользователя `xray`, под которым работает сам прокси.

Подтверждено на живых серверах (чтение от пользователя `xray`, uid 999):

```
/bin/bash /usr/local/bin/xrayebator alerts-setup --token 999999999:AAFake... --chat-id 123456
curl -sS --max-time 20 https://api.telegram.org/bot999999999:AAFake.../getMe
/bin/bash /usr/local/bin/xrayebator dns01-setup --domain ... --token AAFakeDns...
```

Утечка токена бота была не разовой: `xrayebator-monitor.timer` запускает проверку каждые
15 минут, поэтому процесс с токеном в командной строке существовал на каждом тике.

### 2. `quickstart` на свежем Ubuntu 24.04 не находил certbot

На чистом образе развёртывание обрывалось ответом
`{"ok":false,"error":"Certbot с --ip-address и --preferred-profile не найден"}`,
хотя ручной `snap install --classic certbot` в тот же момент ставил 5.9.0. Причина:
`snapd` на 24.04 сразу после первой загрузки доигрывает seed/refresh и перезапускается
сам («Waiting for automatic snapd restart...»), а установка шла дублем кода в quickstart с
`2>/dev/null || true` -- ошибка глоталась.

### 3. Hysteria 2 не восстанавливалась из повреждённого состояния

Если реестр говорил `installed`, а бинарник с диска уже удалён (сбой обновления, ручная
чистка), `hysteria2-install` отвечал `{"ok":true,"already":true}` и ничего не делал, а
`hysteria2-status` честно писал `binary: "absent"`. Пути починки не было.

### 4. Мелочи, найденные тем же прогоном

* `xrayebator channel-test` без `--name` отвечал «Укажите --name профиля» даже когда
  профиль в системе ровно один: `HAPP_DEFAULT_PROFILE` выставляется только внутри
  quickstart-процесса.
* `quickstart` подмешивал в stdout цветные строки файрвола, из-за чего
  `xrayebator quickstart --without-email | jq .ok` падал.

## Что изменилось

### Безопасность

* URL с токеном передаётся `curl` через stdin-конфиг (`-K -`) -- токен бота и `sub_token`
  больше не появляются в `argv`.
* `jq` получает значения-секреты окружением (`$ENV.XRAYEBATOR_JQ_SECRET`), а не `--arg`:
  это пароль Hysteria 2, ключи AmneziaWG, `sub_token`, ключ VLESS Encryption и токен бота
  в момент записи в JSON.
* Команды принимают сам секрет из stdin или файла:
  `--secret-file PATH` / `--secret-stdin` (у quickstart -- `--dns01-secret-file` /
  `--dns01-secret-stdin`). Файл шире `0600` отвергается, после чтения удаляется.
  `--token` и `--aws-secret-access-key` работают, но печатают предупреждение в stderr.
* Десктоп-GUI передаёт DNS-01-креды файлом `0600` по SFTP -- токен не попадает ни в
  локальную, ни в удалённую командную строку.

```bash
# Было (видно в /proc все 30+ секунд выпуска сертификата):
sudo xrayebator dns01-setup --domain sub.example.com --provider cloudflare --token "$CF"

# Стало:
printf 'token=%s\n' "$CF" | sudo xrayebator dns01-setup \
  --domain sub.example.com --provider cloudflare --secret-stdin --email you@example.com
```

### Исправления

* **certbot для IP-сертификатов** ставится единым помощником `_ensure_certbot_ip_tls`:
  ожидание готовности snapd (`snap wait system seed.loaded`), три попытки установки,
  проверка результата по фактическим флагам бинарника (а не по коду возврата snap),
  логи в `/tmp/snap-*.log` вместо stdout.
* **Hysteria 2 самовосстанавливается**: install проверяет наличие бинарника, юнита и
  `server.yaml`, и при их отсутствии снимает запись реестра и проходит обычным путём;
  осиротевший юнит останавливается перед проверкой порта (иначе восстановление упиралось
  в «UDP-порт 443 уже занят»).
* `channel-test` без `--name` использует единственный профиль; при нескольких профилях
  по-прежнему просит имя, чтобы не проверять чужой.
* Статусы файрвола и прогресс snap уходят в stderr -- stdout CLI снова чистый JSON.

### Тесты

* Новый `validation/test-secret-argv.sh`: подставной `curl` доказывает, что секрет
  отсутствует в `argv` и присутствует на stdin, плюс разбор `--secret-file`/`--secret-stdin`
  и отказ файлу с правами шире `0600`.
* Новый `validation/test-certbot-snap-ip.sh`: единственная реализация установки certbot,
  ожидание snapd, повтор, проверка по возможностям бинарника.
* `test-hysteria2-lifecycle.sh` и `test-awg-lifecycle.sh` стали герметичными: пути
  (`HYSTERIA2_BIN`, `HYSTERIA2_UNIT_FILE`, `AWG_SYSCTL_FILE`, `AWG_MODULES_LOAD_FILE` и др.)
  в менеджере переопределяемы, тесты уводят их в tmp. Раньше прогон набора на рабочем
  сервере **удалял настоящий** `/usr/local/bin/hysteria`, а проверка «модуль для другого
  ядра» на сервере с ядром `5.15.0-177` вырождалась в проверку того же ядра.
* `test-channel-test-cli.sh` якорится на ASCII-строку, а не на символ рамки «-» (его не
  матчит `mawk` -- awk по умолчанию в Debian/Ubuntu).
* Всего **49** Bash-валидаций (было 47).

Дополнительно проверено на живых серверах:

* утечка секретов **воспроизведена** на 0.7.2 (2 процесса с токеном бота, 1 с DNS-токеном
  в `/proc`, чтение от непривилегированного `xray`) и **отсутствует** на 0.7.3 (0 процессов);
* самовосстановление Hysteria: удаление `/usr/local/bin/hysteria` при живом реестре ->
  `hysteria2-install --grant-all` вернул бинарник (23.9 МБ), юнит `active`, UDP-сокет на месте;
* `kernel-guard`: три вызова `--enable` дают ровно одно nft-правило, MPTCP выключен,
  после перезагрузки защита на месте.

## Обновление

```bash
sudo xrayebator-update          # полный lifecycle-путь
# либо только менеджер:
sudo xrayebator update main
```

Откат совместим в обе стороны: серверные `--token`/`--aws-secret-access-key` остались,
поэтому старый GUI работает со старым сервером, а новый -- с обоими.

**После обновления стоит один раз проверить бэкенды**, если ранее были сбои обновлений:

```bash
sudo xrayebator backend-status        # installed и state отдельно
sudo xrayebator hysteria2-install     # теперь сам починит повреждённую установку
```
