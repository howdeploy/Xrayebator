# Xrayebator v0.6.5-beta.1 — multi-protocol: Hysteria 2 and AmneziaWG 3.1 join Reality

> ⚠️ **This is a beta.** `0.6.5` is in testing and may be unstable. If you need a proven build, stay on `0.6.0`. Found a problem, have logs or errors — post them as comments on this release (or separate issues): logs are the fastest way for us to fix things.

> An update to the server manager and the **Xrayebator Desktop GUI**. Installs over `0.6.0` — migrations do the work, no need to reconfigure existing servers.

## In two words

Until now the server could run a single protocol — Xray Reality over TCP. When censorship throttles TCP, the whole VPN falls at once: one transport, one point of failure.

`v0.6.5` puts two more transports on the same server and teaches the panel to manage them:

1. **Hysteria 2** — a UDP/QUIC transport: fast on bad links, alive where TCP is cut;
2. **AmneziaWG 3.1** — a system VPN (WireGuard with anti-DPI junk in the headers): full tunnel, native AmneziaVPN apps;
3. **Per-profile grants** — each protocol's key is issued separately and lives in one lifecycle with the profile: revoke, expiry and deletion revoke the backend keys together with VLESS.

```text
┌────────────────────────────────────────────────────────┐
│                      one VPS                           │
│                                                        │
│  Xray (Reality, TCP)      ── ports 443 / high 30xxx    │
│  Hysteria 2 (QUIC, UDP)   ── its own port              │
│  AmneziaWG 3.1 (UDP)      ── awg0, its own port        │
│                                                        │
│  subscription: vless:// + hysteria2:// + HAPP routes   │
└────────────────────────────────────────────────────────┘
        ▲                        ▲                    ▲
        │                        │                    │
   HAPP / v2rayNG          HAPP / Hiddify         AmneziaVPN
   ( Reality+Hysteria )    ( Reality+Hysteria )   ( AmneziaWG 3.1 )
```

The client subscription stays a single one: `hysteria2://` lines are appended to the same subscription bodies (with a kill switch in the GUI), the AWG config is delivered as a `.conf` file or QR, and for the full AmneziaVPN app — in the native `vpn://` format.

## What is new

### 1. A neutral backend registry

The state of the extra protocols lives in the neutral root `/usr/local/etc/xrayebator/` (the `backends.json` registry is 644 with no secrets, runtime state with secrets is 750). The `/usr/local/etc/xray/` directory stays Xray-only. One choke point — `_backend_apply_profile_lifecycle` — runs every profile lifecycle event through all installed backends, so revoke/expiry/deletion never leaves orphaned credentials.

### 2. Hysteria 2 (UDP/QUIC)

- installed from official `HyNetworks/hysteria` releases with sha256 verification, a dedicated `hysteria` system user and its own `hysteria-server.service` (CAP_NET_BIND_SERVICE, auto-restart), QUIC buffer sysctls;
- adaptive TLS: when the subscription has a Let's Encrypt certificate it is copied into the backend (with a renewal deploy-hook), otherwise a self-signed cert is generated — and client links honestly carry `insecure=1`;
- per-profile keys: the password lives in the profile's `.backends.hysteria2`, `server.yaml` is **always regenerated from profiles** — revoking or extending a key is just a regen plus a restart with rollback;
- `hysteria2://` is appended to both subscription bodies (HAPP and v2rayNG), managed by a kill switch without a service restart.

### 3. AmneziaWG 3.1 (system VPN)

- kernel module via DKMS: the primary path is the `amnezia/ppa` PPA, the fallback is a source build (kernels ≥ 5.6 need the full `linux-source` tree);
- junk parameters match the official Amnezia dialect exactly (Jc=5, Jmin/Jmax, H1–H4, S1–S4): the official apps apply this set predictably;
- the **3.1 format is on by default**: `HeaderProtectionKey`, `RandomTrailers`, `S3`/`S4`; the `awg-31` toggle exists with an explicit warning — issued client `.conf` files must be re-downloaded (AmneziaVPN ≥ 5.0.1.5);
- per-profile peers: client keypair + preshared key, addresses from `10.8.1.0/24`; `awg0.conf` is regenerated from profiles;
- the client `.conf` is a full tunnel (`AllowedIPs = 0.0.0.0/0, ::/0`), keepalive 25; in the GUI the key can be taken as `.conf`, QR or "QR · AmneziaVPN" — the native `vpn://` format the app imports fully (a raw `.conf` pasted into the full AmneziaVPN does not reach its tunnel intact).

### 4. Lifecycle: keys do not live their own life

- **Profile creation** does NOT auto-issue a key: the operator picks the protocol in the GUI (or runs an explicit `hysteria2-grant` / `awg-grant`), otherwise every new profile would immediately receive keys from all installed backends;
- **Revoke** rotates the Hysteria password and the AWG peer's keypair+PSK (old configs drop, the address is kept);
- **Expiry/renewal** is a regen from profiles with disabled ones filtered out for backends: an expired profile stops receiving keys, a renewed one comes back;
- **Profile deletion** removes the peer from `awg0.conf` and the password from `server.yaml` in the same command; there are no orphaned credentials.

### 5. GUI: the "additional protocols" panel

- a combined backends block in Server settings: official logos, state (version, port, TLS mode / interface, junk summary), install/uninstall;
- backend key cards per profile — on equal footing with VLESS cards: QR (including "QR · AmneziaVPN"), expiry with presets, revoke, delete; confirmations use the soft danger style;
- profile creation picks the protocol: plain VLESS, Hysteria 2 or AmneziaWG — only the chosen protocol issues a key;
- the Keys page shows hysteria2 lines from the subscription and AWG configs alongside the VLESS links.

### 6. HAPP routing: split routing from bypass groups

The managed HAPP profile can now be assembled from bypass groups (`bypass list/add/remove/reset/bundle`): domains of the chosen groups go direct, the rest goes into the tunnel. The client downloads geo databases through the subscription itself (the `{{GEOIP_URL}}` / `{{GEOSITE_URL}}` / `{{LAST_UPDATED}}` placeholders are resolved per subscriber — the database URL is bound to their token).

### 7. quickstart degrades to `http_tls` instead of dying

Some hosters filter inbound port 80 for foreign sources — Let's Encrypt cannot validate http-01 for a bare IP (`Connection reset by peer` from validation hosts). This used to be a dead end; now:

- the deploy finishes with `degraded:true`, `tls_mode:"http_tls"` and the Certbot reason;
- the subscription stays **loopback-only — there is no public URL at all**: the GUI loads keys over SSH from `http://127.0.0.1:8080/sub/<token>` on the server itself (nothing to leak);
- a self-signed certificate is prepared in advance — for future Hysteria installs;
- the ACME location on :80 stays in place: once the hoster unblocks the port, a re-run of quickstart (idempotent) issues the LE certificate and restores HTTPS.

In the GUI such a server is stored as "Partially configured" with a degraded badge.

### 8. SNI and country

- the SNI candidate list is updated from the 03.09.2026 reachability measurements; the default SNI for new profiles is `www.cloudflare.com` (the most stable);
- subscription keys are labelled with the server country: fragments look like `🇫🇮 Finland · happ-*` — handy when you run several servers.

## Field notes

- **Junk is a dialect, not a number.** The official AmneziaVPN apps apply the Amnezia defaults predictably; their go-tunnel applies custom junk fields incompletely. That is why the generator emits exactly the dialect the official clients understand.
- **A hoster's :80 filter is only visible from outside.** On the VPS itself nginx and the firewall are fine, while certbot gets resets from validation hosts. Diagnosis: tcpdump on :80 plus multi-node probes from different countries. Fix: a ticket to the hoster or the domain TLS mode.
- **Geo databases disagree per ASN.** ipinfo.io and ipwho.is/ip-api can place the same range in different countries (example: NODE HOST LIMITED — Finland vs Germany/Frankfurt). The server country is written to a marker and into key names; on disagreement it is corrected manually.
- **The http_tls fallback cannot serve HAPP geo databases.** The managed profile sends the client to fetch `geoip.dat`/`geosite.dat` through the subscription itself; without a public subscription a client without pre-loaded bases shows "no data". Keys keep working — routing stays default.
- **An `awg0` restart drops the tunnel for all peers for seconds.** Grants/revokes are rare; for stage 1 this is accepted: regen + restart is simpler and more reliable than incremental edits.

## Before you update

### Server requirements

- Debian 12/13 or Ubuntu 22.04/24.04, systemd, bash, root/sudo;
- for AmneziaWG — kernel ≥ 5.6 and a working DKMS build (PPA or sources);
- migrations catch the state up automatically at the first menu run or quickstart.

### Breaking changes

For existing VLESS-only installations there are none: everything is additive, profiles and subscriptions stay compatible. Worth knowing:

- **one AWG key = one device** — two devices on one `.conf` will fight over the endpoint;
- **Hysteria under a self-signed cert works with `insecure=1`** — a deliberate mode until the LE certificate is issued;
- **an `http_tls` server has no public subscription** — keys are fetched over SSH from the GUI (or via curl over SSH on the server).

### Honest limitations

- HAPP's acceptance of `hysteria2://` lines in the subscription bodies and real AWG client connections were verified in a live spike, not CI (network phases cannot be reproduced in CI);
- an `awg0` restart on grant/revoke briefly drops the tunnel for all peers;
- HAPP geo databases are unavailable to the client without pre-loading under the `http_tls` fallback ("no data" is not broken keys);
- the post-quantum PQ route still is not placed into the subscription (the URL is ~2 KB) — that is size, not a bug.

## How to update

### Server

```bash
sudo xrayebator update main
```

Backends are **not installed automatically**: after the update open Server settings → "Multi-protocol backends" and install Hysteria 2 and/or AmneziaWG with the button. Keys are issued per profile — creation goes through the protocol choice.

### Xrayebator Desktop GUI

1. Download the package for your OS from the GitHub Release.
2. Install over the previous version — server cards are preserved.
3. New: the backends panel in Server settings, backend cards on profiles, Hysteria/AWG keys on the Keys page.
4. The "Update Xrayebator" button is now a branch menu: "Auto — as pinned on the server" (the pinned `.current_branch`, otherwise main), "main — latest stable release", "dev — every feature first" (may be unstable — this is how this beta reaches a server before the release).

## Build

The release is built natively for three systems:

- Windows — `Xrayebator-0.6.5-beta.1-win.exe`;
- macOS Apple Silicon — `Xrayebator-0.6.5-beta.1-mac-arm64.dmg` and `.zip` (the ZIP is needed by the built-in auto-update);
- Linux — `Xrayebator-0.6.5-beta.1-linux.AppImage`.

Before the build, typecheck, unit tests and the full Bash validation suite (34 scripts) run on Ubuntu.
