# Xrayebator v0.7 — мультипротокол, PQ на всех транспортах, DNS-01 и переработанная панель

> Обновление серверного менеджера и **Xrayebator Desktop GUI**. Ставится поверх `0.6.0` (и поверх любой `0.6.5-beta`) — миграции доделают всё сами, перенастраивать серверы не нужно. Нашли проблему, есть логи или ошибки — пишите их комментариями к этому релизу или отдельным issue: по логам чиним быстрее всего.

## Изменения с 0.6.5-beta.2

Тот срез кода не менялся, но всё, что накопилось после него (112 коммитов), в бете.2 не было. Коротко, что появилось:

- **PQ на всех транспортах**: `mlkem768x25519plus` больше не прибит к xhttp — `profile-pq --transport tcp|tcp-utls|tcp-xudp|tcp-mux|grpc|xhttp` создаёт пост-квантовый маршрут на любом, со своим инбаундом и портом (VLESS `decryption` — уровня инбаунда).
- **Четыре формата подписки из одного токена**: к HAPP и base64 добавились Clash/mihomo (YAML) и sing-box (JSON), выбор по `?target=` и `User-Agent`, дефолт по-прежнему HAPP.
- **DNS-01 как фолбэк развёртывания** плюс `repair-dns01` для уже деградировавшей подписки: цепочка «существующий серт → http-01 по IP → DNS-01 → `http_tls`».
- **Staging-контур ACME и `dns01-test`**: проверочный выпуск в staging со своей линией и без побочных эффектов — чтобы отладка не выжигала прод-квоту Let's Encrypt.
- **Лимиты трафика на профиль**: учёт через Stats API, авто-отключение при превышении, `profile-limit` / `traffic-check`, чип и диалог в GUI.
- **Telegram-алерты и мониторинг**: `alerts-setup`, `monitor-check` каждые 15 минут (юниты, бэкенды, сроки, лимиты, живость подписки, TLS-режим, SNI-проба, ребуты). **В GUI поверхности алертов больше нет** — только терминал.
- **`channel-test`**: проверка каналов настоящим клиентом Xray, без Let's Encrypt, включая PQ-маршруты.
- **GUI-волна по фидбеку**: страница «Существующие профили» отдельно от создания, разделы в настройках сервера, сворачиваемая карточка «Подписка и TLS», компактная форма развёртывания, ключи бэкендов у профиля, зелёная кнопка «Готово».
- **Исправления с живых серверов**: `profile-pq` больше не теряет базовый маршрут, `profile-delete` не оставляет осиротевших инбаундов, SNI-проба не принимает недостижимые хосты, `?target=v2ray` не отдаёт HAPP-тело, учёт трафика действительно считает, AWG поднимается после ребута, jq 1.6 не ломает PQ на Ubuntu 22.04.
- **Документация** синхронизирована на трёх языках и сверена с кодом; тестов стало 42 скрипта (было 28).

## Если объяснить в двух словах

Раньше сервер умел один протокол — Xray Reality поверх TCP. Цензура душит TCP — и весь VPN падает целиком: один транспорт, одна точка отказа.

`v0.7` ставит на тот же сервер ещё два транспорта, а панель — управлять ими:

1. **Hysteria 2** — UDP/QUIC-транспорт: быстрый на плохих каналах, живёт там, где TCP режут;
2. **AmneziaWG 3.1** — системный VPN (WireGuard с анти-DPI «мусором» в заголовках): полный туннель, нативные приложения AmneziaVPN;
3. **Гранты по профилю** — ключ каждого протокола выдаётся отдельно и живёт в одном жизненном цикле с профилем: revoke, срок, удаление отзывают бэкенд-ключи вместе с VLESS.

```text
┌────────────────────────────────────────────────────────┐
│                      один VPS                          │
│                                                        │
│  Xray (Reality, TCP)      ── порты 443 / высокие 30xxx │
│  Hysteria 2 (QUIC, UDP)   ── свой порт                 │
│  AmneziaWG 3.1 (UDP)      ── awg0, свой порт           │
│                                                        │
│  подписка: vless:// + hysteria2:// + маршруты HAPP     │
└────────────────────────────────────────────────────────┘
        ▲                        ▲                    ▲
        │                        │                    │
   HAPP / v2rayNG          HAPP / Hiddify         AmneziaVPN
   ( Reality+Hysteria )    ( Reality+Hysteria )   ( AmneziaWG 3.1 )
```

Клиентская подписка остаётся одной: строки `hysteria2://` добавляются в те же тела подписки (с килл-свитчем в GUI), AWG-конфиг выдаётся как файл `.conf` или QR, а для полного AmneziaVPN — в родном формате `vpn://`. Один токен отдаёт четыре тела: HAPP, base64 v2ray, Clash/mihomo и sing-box.

## Что нового

### 1. Нейтральный реестр бэкендов

Состояние допротоколов живёт в нейтральном корне `/usr/local/etc/xrayebator/` (реестр `backends.json` — 644 без секретов, runtime-состояние с секретами — 750). Каталог `/usr/local/etc/xray/` остаётся только про Xray. Один choke point — `_backend_apply_profile_lifecycle` — проводит каждый жизненный цикл профиля через все установленные бэкенды, так что revoke/срок/удаление не оставляют осиротевших креденшелов.

### 2. Hysteria 2 (UDP/QUIC)

- установка из официальных релизов `HyNetworks/hysteria` с проверкой sha256, отдельный системный пользователь `hysteria` и свой `hysteria-server.service` (CAP_NET_BIND_SERVICE, авто-рестарт), QUIC-буферы sysctl;
- TLS адаптивный: если у подписки есть Let's Encrypt-сертификат — он копируется в бэкенд (с deploy-hook'ом на продление), иначе генерируется self-signed — и клиентские ссылки честно получают `insecure=1`;
- ключи per-profile: пароль лежит в `.backends.hysteria2` профиля, `server.yaml` **всегда регенерируется из профилей** — отозвать или продлить ключ это просто реген + рестарт с откатом;
- `hysteria2://` добавляется в оба тела подписки (HAPP и v2rayNG), управляется килл-свитчем без рестарта сервиса.

### 3. AmneziaWG 3.1 (системный VPN)

- kernel-модуль через DKMS: основной путь — PPA `amnezia/ppa`, фолбэк — сборка из исходников (для ядра ≥5.6 нужен полный `linux-source`); модуль грузится при старте ОС, иначе после ребута туннель лежал бы с «активной» карточкой;
- junk-параметры — один в один с официальным Amnezia-диалектом (Jc=5, Jmin/Jmax, H1–H4, S1–S4): их родные приложения применяют предсказуемо;
- формат **3.1 включён по умолчанию**: `HeaderProtectionKey`, `RandomTrailers`, `S3`/`S4`; тумблер `awg-31` существует с явным предупреждением — старые клиентские `.conf` нужно скачать заново (AmneziaVPN ≥ 5.0.1.5);
- peer'ы per-profile: клиентская пара ключей + preshared key, адреса из `10.8.1.0/24`; `awg0.conf` регенерируется из профилей;
- клиентский `.conf` — полный туннель (`AllowedIPs = 0.0.0.0/0, ::/0`), keepalive 25; в GUI ключ можно забрать `.conf`, QR или «QR · AmneziaVPN» — родной `vpn://`-формат, который приложение импортирует целиком (обычный `.conf`, вставленный в полное AmneziaVPN, до туннеля доходит не intact).

### 4. PQ (VLESS Encryption) на всех транспортах

- `xrayebator profile-pq --name N [--transport tcp|tcp-utls|tcp-xudp|tcp-mux|grpc|xhttp]` добавляет пост-квантовый маршрут (`mlkem768x25519plus`) на любой транспорт;
- VLESS `decryption` — уровня инбаунда, поэтому PQ-маршрут получает собственный инбаунд и порт с общим ключом из `.vless_decryption`; обычные маршруты остаются `encryption=none` и работают у всех клиентов;
- PQ-маршруты не попадают в base64/v2ray-тело (клиент без ML-KEM к ним всё равно не подключится) и пропускаются с причиной в Clash/sing-box; в HAPP-теле они остаются;
- `profiles` отдаёт аддитивный счётчик `pq_routes` — верхнеуровневый `pq_enabled` описывает только первый маршрут.

### 5. Подписка: четыре формата из одного токена

- HAPP, base64 v2ray, Clash/mihomo (YAML) и sing-box (JSON) собираются из одного набора ссылок; формат выбирается по `?target=` и `User-Agent`, дефолт — HAPP, чтобы уже выданные ссылки не сломались;
- маршруты, которые клиент не умеет (PQ, xhttp в sing-box, xhttp в Clash без `?xhttp=1`), пропускаются с причиной, а не ломают конфиг целиком;
- `subscription-userinfo` отдаётся во всех форматах; ссылки форматов кэшируются в карточке сервера, поэтому в GUI не «дорастают» после ответа SSH;
- в GUI это **дополнительный вид, а не обязанность**: по умолчанию страница «Ключи» отдаёт основной набор — подписку HAPP/v2ray и VLESS-ссылки, как раньше, — а форматы Clash/sing-box включаются переключателем «Форматы Clash / sing-box» в шапке страницы. Без него один и тот же токен печатался трижды на каждый профиль, и ключ выглядел задвоенным.

### 6. DNS-01 и ACME

- `dns01-setup --domain --provider cloudflare|route53` выпускает сертификат по TXT-записи — входящий порт 80 не нужен вовсе;
- `repair-dns01` переводит уже деградировавшую `http_tls`-подписку на домен, идемпотентно;
- staging-контур (`--staging`) и `dns01-test` — проверочный выпуск отдельной линией, без деплой-хука и без побочных эффектов: отладка больше не выжигает прод-квоту (5 сертификатов на набор идентификаторов в 168 часов);
- `dns01-status` определяет контур по самому сертификату и понимает обе формы записи хука (`deploy-hook` / `renew_hook`).

### 7. Лимиты трафика на профиль

- учёт через Stats API Xray (loopback `dokodemo-door`), дельты по watermark — рестарт Xray не теряет уже посчитанные байты;
- `profile-limit --name N --limit 500MB|2TB|none [--reset]`, `traffic-check` каждые 5 минут; при превышении клиент снимается с инбаунда и возвращается, когда лимит подняли;
- срок и лимит кросс-проверяются: профиль не включится, пока действует второе ограничение;
- в GUI — чип в карточке профиля и диалог лимита.

### 8. Telegram-алерты и мониторинг

- `alerts-setup` валидирует токен через `getMe` и доставляет тестовое сообщение **до** записи конфига — недопоставляемый чат не оставляет полуконфигурации;
- `monitor-check` раз в 15 минут: юниты, установленные бэкенды, приближение и истечение срока профилей, упёршиеся в лимит профили, живость подписки, деградация TLS-режима, ежедневная SNI-проба, ребуты;
- дедупликация, «не чаще раза в N», повторная попытка при неудачной отправке — в `monitor-state.json`;
- **в десктоп-приложении поверхности алертов нет** — токен бота ходит через один вход, терминал.

### 9. Жизненный цикл: ключи не живут своей жизнью

- **Создание профиля** — ключ НЕ выдаётся автоматически: оператор выбирает протокол в GUI (или даёт явный `hysteria2-grant` / `awg-grant`), иначе каждому новому профилю приходили бы ключи ото всех установленных бэкендов сразу;
- **Revoke** — ротация пароля Hysteria и пары ключей+PSK peer'а AWG (старые конфиги отваливаются, адрес сохраняется);
- **Срок/продление** — для бэкендов это реген из профилей с фильтром отключённых: истёкший профиль перестаёт получать ключ, продлённый возвращается;
- **Удаление профиля** — peer снимается с `awg0.conf`, пароль уходит из `server.yaml` в той же команде; осиротевших креденшелов нет.

### 10. GUI: разделы, страница профилей и компактные карточки

- «Настройки сервера» разбиты на разделы вместо одной длинной прокрутки; панели скрываются атрибутом, поэтому введённое не теряется при переключении;
- **страница «Существующие профили»** отдельно от создания: поиск по имени/SNI/домену подписки, фильтр «Все/Активные/Отключённые», счётчик карточек; оба экрана живут в одном компоненте, поэтому переключение не поднимает вторую SSH-сессию;
- карточка **«Подписка и TLS»** — сворачиваемая: иконка-сертификат, режим бейджем, три значения в моно-боксах;
- форма развёртывания короче на четверть: IP и SSH-порт в одной строке, PQ и DNS-01 в общем блоке «Дополнительно», подсказка о host key — футер карточки прогресса;
- панель бэкендов в «Настройках сервера»: официальные логотипы, состояние (версия, порт, TLS-режим / интерфейс, сводка junk), установка/удаление, кнопка «Запустить» у простаивающего бэкенда;
- ключи бэкендов у профиля — на равных с VLESS: QR (включая «QR · AmneziaVPN»), срок с пресетами, Revoke, удаление; подтверждения — мягкий danger-soft.

### 11. HAPP-маршрутизация: split routing из bypass-групп

Управляемый HAPP-профиль умеет собираться из bypass-наборов (`bypass list/add/remove/reset/bundle`): домены выбранных групп уходят direct, остальное — в туннель. Geo-базы клиент скачивает через саму подписку (плейсхолдеры `{{GEOIP_URL}}` / `{{GEOSITE_URL}}` / `{{LAST_UPDATED}}` подставляются на каждого подписчика — адрес базы привязан к его токену).

### 12. quickstart деградирует в `http_tls`, а не умирает

Часть хостеров фильтрует входящий порт 80 для зарубежных источников — Let's Encrypt не может проверить http-01 для голого IP (`Connection reset by peer` от validation-хостов). Раньше это был dead-end, теперь:

- деплой завершается с `degraded:true`, `tls_mode:"http_tls"` и причиной certbot;
- подписка остаётся **только на loopback — публичного URL нет вовсе**: ключи GUI загружает по SSH с `http://127.0.0.1:8080/sub/<token>` на самом сервере (утекать нечему);
- self-signed-сертификат готовится заранее — для будущих Hysteria-инсталлов;
- если передан домен и токен DNS-провайдера, фолбэк идёт через DNS-01 и подписка остаётся на HTTPS;
- ACME-location на :80 сохраняется: хостер разблокировал порт → повторный quickstart (идемпотентный) выпускает LE-серт и возвращает HTTPS.

В GUI такой сервер хранится как «Настроен частично» с пометкой деградации.

### 13. SNI и страна

- `probe-test` и выбор SNI по умолчанию руководствуются строгим критерием: завершённое TLS 1.3-рукопожатие с проверенным сертификатом **и** ответ по HTTP, два замера, бюджет 3 с на попытку. Недостижимый `dest` больше не выдаётся новым профилям;
- ключи подписки подписаны страной сервера: фрагменты выглядят как `🇫🇮 Finland · happ-*` — удобно, когда серверов несколько.

## Что ещё попало в ветку

- `profile-pq` больше не выбрасывает базовый маршрут профиля, который просили расширить (одно-маршрутная форма разворачивается в `routes[]`);
- `profile-delete` не оставляет осиротевших инбаундов: набор портов считается как union верхнего `.port` и всех `routes[].port`;
- `?target=v2ray` не отдаёт HAPP-тело; правило, выкидывавшее xhttp-маршрут из HAPP, снято — оно молча удаляло рабочий `xhttp-pq`;
- jq 1.6 не ломает PQ (`label` — ключевое слово): маршрут создаётся и на Ubuntu 22.04 / Debian 12;
- `quickstart --pq` перестал быть мёртвым кодом — блок перенесён из ветки ошибки после её возврата;
- учёт трафика включён там, где политика Xray его реально отдаёт (`statsUserUplink/Downlink`), плюс ремонтная миграция для серверов с ранним маркером;
- AWG: `S1 != S2`, подпись и цвет карточки из одного поля, `revoke` ротирует и PSK;
- `inspect --json` больше не рапортует установленные бэкенды как отсутствующие; `xrayebator-uninstall` снимает бэкенды до удаления состояния;
- `revoke --full` работает на single-route профилях; `profile-delete` печатает только JSON;
- GUI-мелочи по фидбеку: строка профиля в одну линию, «действует до» без прыжков карточки, меню ветки обновления на HeroUI `Dropdown`, зелёная кнопка «Готово» без размытия.

## Стабильность и безопасность

- **TLS и ACME.** Staging-контур и `dns01-test` позволяют проверить домен и токен, не выжигая прод-квоту Let's Encrypt; `dns01-status` определяет контур по самому сертификату и понимает обе формы записи хука; короткоживущий IP-сертификат больше не воюет с дистрибутивным `certbot.timer`; `repair-dns01` не двигает порт подписки.
- **Доступ.** SSH host key закрепляется при первом успешном входе, режим root/sudo выбирается явно, пароли и ключи живут в системном хранилище; креды DNS-01 хранятся на сервере файлом `0600` root и в GUI не сохраняются; токен Telegram-бота не печатается ни в одной команде и настраивается только из терминала.
- **Подписка.** PQ-маршруты не попадают в тела, которые клиент без ML-KEM всё равно не осилит, а неподдерживаемые маршруты пропускаются с причиной вместо битого конфига; удаление профиля больше не оставляет осиротевших инбаундов, продолжавших обслуживать удалённый профиль.
- **Лимиты.** Достижение лимита трафика снимает клиента с инбаунда и возвращает его при поднятии лимита; срок и лимит кросс-проверяются, поэтому одно ограничение не обходится через второе.
- **Сеть.** SNI по умолчанию выбирается только по строгому критерию — завершённое TLS 1.3-рукопожатие с проверенным сертификатом **и** ответ по HTTP, — поэтому новые профили не получают заведомо мёртвые маршруты.
- **Надёжность.** Миграции идемпотентны и зарегистрированы во всех путях входа; `safe_restart_xray` валидирует конфиг и откатывается при ошибке; UFW-правила и nginx-vhosts ведутся по манифесту, чтобы удаление не оставляло хвостов.

## Насколько это проверено

Автоматически:

- Bash-валидация: **42 скрипта** (было 28) — новые: PQ на всех транспортах, форматы подписки, DNS-01/certbot, `quickstart` TLS-fallback, лимиты трафика, алерты/мониторинг, жизненный цикл Hysteria 2 и AmneziaWG, реестр бэкендов, `channel-test`, HAPP client routing, достижимость SNI, синхронизация портов легаси-профилей, совместимость jq 1.6;
- GUI: 25 файлов Vitest (172 теста) — AWG-экспорт (`vpn://`, range-таймеры, qCompress), backend-manager, инспектор, рендер страниц настроек и профилей, паритет i18n `ru`/`en`/`zh`; typecheck и сборка чистые;
- CI на ubuntu-24.04 прогоняет все 42 скрипта; сборки — на трёх ОС.

Живыми прогонами: **три развёртывания** с живыми замерами — два контрольных с нуля на Ubuntu 22.04 (дефолтный режим GUI и с включённым PQ-маршрутом) и рабочий сервер, развёрнутый ранее, где проверены профили, форматы подписки и оба бэкенда; плюс контрольные развёртывания на четырёх дистрибутивах (Ubuntu 22.04/24.04, Debian 12/13), включая ветку `http_tls`-фолбэка на хостере с фильтрацией `:80`. На всех трёх — проверка каналов настоящим клиентом Xray, включая пост-квантовые маршруты (HTTP 200, ≈170–330 мс); все четыре формата подписки снаружи; установка и гранты Hysteria 2 и AmneziaWG; импорт `vpn://` в AmneziaVPN ≥ 5.0.1.5; самообновление `main → dev` через CLI.

И ручная проверка на устройствах: все маршруты всех трёх развёртываний подключаются и работают с телефона и с ПК через **HAPP** и **Hiddify** — то есть приём ссылок из подписки проверен не только на сервере, но и живыми клиентами.

## Важно перед обновлением

### Требования к серверу

- Debian 12/13 или Ubuntu 22.04/24.04, systemd, bash, root/sudo;
- для AmneziaWG — ядро ≥ 5.6 и рабочая DKMS-сборка (PPA или исходники);
- миграции догонят состояние автоматически при первом запуске меню или quickstart.

### Breaking changes

Для существующих VLESS-установок их нет: всё аддитивно, профили и подписка совместимы. Знать стоит:

- **один AWG-ключ = одно устройство** — два устройства на одном `.conf` будут воевать за endpoint;
- **Hysteria под self-signed работает с `insecure=1`** — это осознанный режим до выпуска LE-сертификата;
- **`http_tls`-сервер не имеет публичной подписки** — ключи забираются по SSH из GUI (или curl'ом по SSH на сервере);
- **PQ-маршрут не входит в base64/v2ray-тело** — в HAPP он есть, остальным клиентам нужен ML-KEM;
- **Telegram-алерты настраиваются только через CLI** — в GUI этой поверхности больше нет.

### Честные ограничения

- маршруты всех трёх развёртываний проверены и на устройствах — с телефона и с ПК через HAPP и Hiddify подключаются и работают; отдельного замера задержек внутри приложений не делали, цифры в этом релизе — из `channel-test` на сервере;
- реальное подключение AmneziaWG-клиентов и установка бэкендов из сети проверены живым спайком, не CI — сетевые фазы DKMS и туннелей в CI не воспроизводятся;
- рестарт `awg0` при гранте/отзыве кратко роняет туннель всем peer'ам;
- geo-базы HAPP при `http_tls`-фолбэке недоступны клиенту без предзагрузки («no data» — не поломка ключей).

## Как обновиться

### Сервер

```bash
sudo xrayebator update main
```

Бэкенды **не ставятся сами**: после обновления откройте «Настройки сервера» → раздел «Доп. протоколы» и установите Hysteria 2 и/или AmneziaWG кнопкой. Ключи выдаются по профилям — создание через выбор протокола.

### Xrayebator Desktop GUI

1. Скачайте пакет для своей ОС из GitHub Release.
2. Установите поверх предыдущей версии — карточки серверов сохранятся.
3. Новое: страница «Существующие профили», разделы настроек, компактная карточка «Подписка и TLS», бэкенд-карточки у профилей, ключи Hysteria/AWG на странице «Ключи».
4. Кнопка «Обновить Xrayebator» — меню веток: «Авто — как закреплено на сервере», «main — последняя стабильная версия», «dev — все фишки сразу» (может быть нестабильной — именно так на сервер ставится эта бета до релиза).

## Сборка

Релиз собирается нативно для трёх систем:

- Windows — `Xrayebator-0.7.0-win.exe`;
- macOS Apple Silicon — `Xrayebator-0.7.0-mac-arm64.dmg` и `.zip` (ZIP нужен встроенному автообновлению);
- Linux — `Xrayebator-0.7.0-linux.AppImage`.

Перед сборкой на Ubuntu прогоняются typecheck, unit-тесты и полный набор Bash-валидаций (42 скрипта).
