# Xrayebator v0.6.5-beta.2 — мультипротокол: к Reality добавились Hysteria 2 и AmneziaWG 3.1

> ⚠️ **Это бета-версия.** `0.6.5` находится в тестировании и может быть нестабильной. Если нужен проверенный вариант — ставьте `0.6.0`. Нашли проблему, есть логи или ошибки — пишите их комментариями к этому релизу (или отдельным issue): по логам чиним быстрее всего.

> Обновление серверного менеджера и **Xrayebator Desktop GUI**. Ставится поверх `0.6.0` — миграции доделают всё сами, перенастраивать серверы не нужно.

## Изменения с beta.1

Код менеджера и GUI **не менялся** — beta.2 это сборка beta.1 плюс полный штамп живой валидации и чистка документации. Всё, что произошло между двумя срезами:

### Живая матрица: 8 разворотов с нуля на 4 дистрибутивах и 4 хостерах

Контрольная сетка перед продолжением разработки: 8 разворотов с нуля, распределённых по 4 дистрибутивам (Ubuntu 22.04, Ubuntu 24.04, Debian 12, Debian 13) и 4 независимым хостерам. Имена провайдеров сознательно не раскрываются — список читаем стороной мониторинга РФ; что пришлось чинить — так это то, что все четыре точки проверены на достижимость и отзывчивость именно из российских сетей, т. е. релевантность для целевой аудитории подтверждена.

Состав разворотов:

- **7 полных разворотов с бэкендом** — `install.sh` + `quickstart` (регистрация в ACME с email, выпуск сертификата Let's Encrypt, публикация подписки, создание профиля, рабочий data-plane) на каждой из комбинаций система/хостер;
- **1 разворот** — путь деградации на хостере, блокирующем порт 80: `http_tls`-фолбэк отработал (деплой не умирает, подписка публикуется по HTTP loopback, self-signed сертификат подготовлен для будущих бэкендов), сервер остаётся управляемым.

Итог: стандартный `ip_tls`-путь воспроизводится на всех 4 дистрибутивах и не зависит от конкретного хостера; ветка `http_tls`-фолбэка подтверждена на живом блоке `:80`; сетевая достижимость из России подтверждена на всех 4 провайдерах. Матрица считается закрытой до следующего регрессионного прогона.

### Обе TLS-ветки живьём на двух немецких серверах

Контрольные развороты с нуля на двух разных серверах хостера в немецком IP-диапазоне (одна IP-нода — 1CPU/1GB, вторая — переустановленная ОС, Debian 12):

- **стандартный `ip_tls`-путь**: `install.sh` (~32с) + `quickstart --without-email` (~74с) на ноде 1CPU/1GB — LE http-01 проходит, сертификат на IP короткоживущий с авто-продлением таймером каждые 12 часов, подписка публично отвечает 200, все Reality-порты TLS-живые с правильным SNI;
- **`http_tls`-фолбэк** (сервер, чей хостер фильтрует :80): деплой не умирает, ключи забираются по SSH с loopback, self-signed сертификат подготовлен для будущих бэкендов, повторный quickstart идемпотентен;
- **самообновление на `dev` через CLI** (поток за кнопкой GUI «Обновить → dev») после установки с `main`: менеджер стоит на dev HEAD, `backend-status`/`profiles` (контракт GUI 0.6.5) отвечают.

Итог: обычная установка не сломана; обе ветки (`ip_tls` и `http_tls`) подтверждены живыми серверами. Прежние «застрявшие деплои» — это молчаливое долгое ожидание apt/certbot на слабых машинах без промежуточного прогресса плюс блок TCP-порта хостером после серии SSH-сессий — инцидент хостера, снялся переустановкой ОС, в коде не воспроизводится.

### Путь самообновления проверен end to end

Установка на `main`, затем CLI-самообновление на `dev` (поток за кнопкой GUI «Обновить → dev»): менеджер оказывается на dev HEAD, `backend-status` / `profiles` — контракт GUI 0.6.5 — отвечают.

### Документация синхронизирована на трёх языках

Структурный аудит `docs/` нашёл дрейф: в EN `configuration.md` был раздел «HAPP provisioning paths» (quickstart email/without-email, `http_tls`-деградация, `inspect`, `happ-setup`), отсутствовавший в ru/zh локалях. Перенесён с переводами; структура всех трёх локалей теперь совпадает попарно (desktop-gui, troubleshooting и релиз-доки уже были синхронны). Мойибаке, оставшийся в релиз-нотах beta.1, исправлен — этот файл его чистая копия.

## Если объяснить в двух словах

До сих пор сервер умел один протокол — Xray Reality поверх TCP. Цензура душит TCP — и весь VPN падает целиком: один транспорт, одна точка отказа.

`v0.6.5` ставит на тот же сервер ещё два транспорта, а панель — управлять ими:

1. **Hysteria 2** — UDP/QUIC-транспорт: быстрый на плохих каналах, живёт там, где TCP режут;
2. **AmneziaWG 3.1** — системный VPN (WireGuard с анти-DPI «мусором» в заголовках): полный туннель, нативные приложения AmneziaVPN;
3. **Гранты по профилю** — ключ каждого протокола выдаётся отдельно и живёт в одном жизненном цикле с профилем: revoke, срок, удаление отзывают бэкенд-ключи вместе с VLESS.

```text
┌────────────────────────────────────────────────────────┐
│                      один VPS                          │
│                                                        │
│  Xray (Reality, TCP)      ── порты 443 / высокие 30xxx │
│  Hysteria 2 (QUIC, UDP)   ── свой порт                 │
│  AmneziaWG 3.1 (UDP)      ── awg0, свой порт           │
│                                                        │
│  подписка: vless:// + hysteria2:// + маршруты HAPP     │
└────────────────────────────────────────────────────────┘
        ▲                        ▲                    ▲
        │                        │                    │
   HAPP / v2rayNG          HAPP / Hiddify         AmneziaVPN
   ( Reality+Hysteria )    ( Reality+Hysteria )   ( AmneziaWG 3.1 )
```

Клиентская подписка остаётся одной: строки `hysteria2://` добавляются в те же тела подписки (с килл-свитчем в GUI), AWG-конфиг выдаётся как файл `.conf` или QR, а для полного AmneziaVPN — в родном формате `vpn://`.

## Что нового

### 1. Нейтральный реестр бэкендов

Состояние допротоколов живёт в нейтральном корне `/usr/local/etc/xrayebator/` (реестр `backends.json` — 644 без секретов, runtime-состояние с секретами — 750). Каталог `/usr/local/etc/xray/` остаётся только про Xray. Один choke point — `_backend_apply_profile_lifecycle` — проводит каждый жизненный цикл профиля через все установленные бэкенды, так что revoke/срок/удаление не оставляют осиротевших креденшелов.

### 2. Hysteria 2 (UDP/QUIC)

- установка из официальных релизов `HyNetworks/hysteria` с проверкой sha256, отдельный системный пользователь `hysteria` и свой `hysteria-server.service` (CAP_NET_BIND_SERVICE, авто-рестарт), QUIC-буферы sysctl;
- TLS адаптивный: если у подписки есть Let's Encrypt-сертификат — он копируется в бэкенд (с deploy-hook'ом на продление), иначе генерируется self-signed — и клиентские ссылки честно получают `insecure=1`;
- ключи per-profile: пароль лежит в `.backends.hysteria2` профиля, `server.yaml` **всегда регенерируется из профилей** — отозвать или продлить ключ это просто реген + рестарт с откатом;
- `hysteria2://` добавляется в оба тела подписки (HAPP и v2rayNG), управляется килл-свитчем без рестарта сервиса.

### 3. AmneziaWG 3.1 (системный VPN)

- kernel-модуль через DKMS: основной путь — PPA `amnezia/ppa`, фолбэк — сборка из исходников (для ядра ≥5.6 нужен полный `linux-source`);
- junk-параметры — один в один с официальным Amnezia-диалектом (Jc=5, Jmin/Jmax, H1–H4, S1–S4): их родные приложения применяют предсказуемо;
- формат **3.1 включён по умолчанию**: `HeaderProtectionKey`, `RandomTrailers`, `S3`/`S4`; тумблер `awg-31` существует с явным предупреждением — старые клиентские `.conf` нужно скачать заново (AmneziaVPN ≥ 5.0.1.5);
- peer'ы per-profile: клиентская пара ключей + preshared key, адреса из `10.8.1.0/24`; `awg0.conf` регенерируется из профилей;
- клиентский `.conf` — полный туннель (`AllowedIPs = 0.0.0.0/0, ::/0`), keepalive 25; в GUI ключ можно забрать `.conf`, QR или «QR · AmneziaVPN» — родной `vpn://`-формат, который приложение импортирует целиком (обычный `.conf`, вставленный в полное AmneziaVPN, до туннеля доходит не intact).

### 4. Жизненный цикл: ключи не живут своей жизнью

- **Создание профиля** — ключ НЕ выдаётся автоматически: оператор выбирает протокол в GUI (или даёт явный `hysteria2-grant` / `awg-grant`), иначе каждому новому профилю приходили бы ключи ото всех установленных бэкендов сразу;
- **Revoke** — ротация пароля Hysteria и пары ключей+PSK peer'а AWG (старые конфиги отваливаются, адрес сохраняется);
- **Срок/продление** — для бэкендов это реген из профилей с фильтром отключённых: истёкший профиль перестаёт получать ключ, продлённый возвращается;
- **Удаление профиля** — peer снимается с `awg0.conf`, пароль уходит из `server.yaml` в той же команде; осиротевших креденшелов нет.

### 5. GUI: панель «дополнительные протоколы»

- общий блок бэкендов в «Настройках сервера»: официальные логотипы, состояние (версия, порт, TLS-режим / интерфейс, сводка junk), установка/удаление;
- карточки бэкенд-ключей у профиля — на равных с VLESS: QR (включая «QR · AmneziaVPN»), срок с пресетами, Revoke, удаление; подтверждения — мягкий danger-soft;
- при создании профиля выбирается протокол: обычный VLESS или Hysteria 2 / AmneziaWG — ключ получит только выбранный протокол;
- страница «Ключи» показывает hysteria2-строки из подписки и AWG-конфиги наравне с VLESS-ссылками.

### 6. HAPP-маршрутизация: split routing из bypass-групп

Управляемый HAPP-профиль теперь умеет собираться из bypass-наборов (`bypass list/add/remove/reset/bundle`): домены выбранных групп уходят direct, остальное — в туннель. Geo-базы клиент скачивает через саму подписку (плейсхолдеры `{{GEOIP_URL}}` / `{{GEOSITE_URL}}` / `{{LAST_UPDATED}}` подставляются на каждого подписчика — адрес базы привязан к его токену).

### 7. quickstart деградирует в `http_tls`, а не умирает

Часть хостеров фильтрует входящий порт 80 для зарубежных источников — Let's Encrypt не может проверить http-01 для голого IP (`Connection reset by peer` от validation-хостов). Раньше это был dead-end, теперь:

- деплой завершается с `degraded:true`, `tls_mode:"http_tls"` и причиной certbot;
- подписка остаётся **только на loopback — публичного URL нет вовсе**: ключи GUI загружает по SSH с `http://127.0.0.1:8080/sub/<token>` на самом сервере (утекать нечему);
- self-signed-сертификат готовится заранее — для будущих Hysteria-инсталлов;
- ACME-location на :80 сохраняется: хостер разблокировал порт → повторный quickstart (идемпотентный) выпускает LE-серт и возвращает HTTPS.

В GUI такой сервер хранится как «Настроен частично» с пометкой деградации.

### 8. SNI и страна

- список SNI-кандидатов обновлён по замерам достижимости 03.09.2026; дефолт новых профилей — `www.cloudflare.com` (самый стабильный);
- ключи подписки подписаны страной сервера: фрагменты выглядят как `🇫🇮 Finland · happ-*` — удобно, когда серверов несколько.

## Полевые заметки

- **Мусор (junk) — это диалект, а не число.** Родные приложения AmneziaVPN применяют набор Amnezia-дефолтов предсказуемо; кастомные junk-поля их go-туннель применяет неполностью. Поэтому генератор выдаёт ровно тот диалект, который понимают официальные клиенты.
- **Фильтрация :80 у хостера видна только снаружи.** На самом VPS nginx и firewall исправны, а `certbot` получает reset от validation-хостов. Диагностика: tcpdump на :80 + мультиузловые пробы с разных стран. Лечение — тикет хостеру или доменный TLS-режим.
- **Geo-базы расходятся по ASN.** ipinfo.io и ipwho.is/ip-api могут разнести один и тот же диапазон по разным странам (пример: NODE HOST LIMITED — Финляндия против Germany/Frankfurt). Страна сервера пишется в маркер и в имена ключей; при расхождении правится вручную.
- **http_tls-фолбэк не даёт HAPP geo-баз.** Управляемый профиль шлёт клиента за `geoip.dat`/`geosite.dat` через саму подписку; без публичной подписки клиент без предзагруженных баз покажет «no data». Ключи при этом работают — маршрутизация остаётся дефолтной.
- **Рестарт `awg0` роняет туннель на секунды всем peer'ам.** Гранты/отзывы редки, для stage 1 это принято: реген + рестарт проще и надёжнее инкрементальных правок.

## Важно перед обновлением

### Требования к серверу

- Debian 12/13 или Ubuntu 22.04/24.04, systemd, bash, root/sudo;
- для AmneziaWG — ядро ≥ 5.6 и рабочая DKMS-сборка (PPA или исходники);
- миграции догонят состояние автоматически при первом запуске меню или quickstart.

### Breaking changes

Для существующих VLESS-установок их нет: всё аддитивно, профили и подписка совместимы. Знать стоит:

- **один AWG-ключ = одно устройство** — два устройства на одном `.conf` будут воевать за endpoint;
- **Hysteria под self-signed работает с `insecure=1`** — это осознанный режим до выпуска LE-сертификата;
- **`http_tls`-сервер не имеет публичной подписки** — ключи забираются по SSH из GUI (или curl'ом по SSH на сервере).

### Честные ограничения

- приём `hysteria2://`-строк в телах подписки HAPP и реальное подключение AWG-клиентов проверены живым спайком, не CI (сетевые фазы в CI не воспроизводятся);
- рестарт `awg0` при гранте/отзыве кратко роняет туннель всем peer'ам;
- geo-базы HAPP при `http_tls`-фолбэке недоступны клиенту без предзагрузки («no data» — не поломка ключей);
- пост-квантовый PQ-маршрут по-прежнему не кладётся в подписку (URL ~2 КБ) — это размер, а не баг.

## Как обновиться

### Сервер

```bash
sudo xrayebator update main
```

Бэкенды **не ставятся сами**: после обновления откройте «Настройки сервера» → «Мультипротокольные бэкенды» и установите Hysteria 2 и/или AmneziaWG кнопкой. Ключи выдаются по профилям — создание через выбор протокола.

### Xrayebator Desktop GUI

1. Скачайте пакет для своей ОС из GitHub Release.
2. Установите поверх предыдущей версии — карточки серверов сохранятся.
3. Новое: панель бэкендов в «Настройках сервера», бэкенд-карточки у профилей, ключи Hysteria/AWG на странице «Ключи».
4. Кнопка «Обновить Xrayebator» теперь меню веток: «Авто — как закреплено на сервере» (прежде закреплённая `.current_branch`, иначе main), «main — последняя стабильная версия», «dev — все фишки сразу» (может быть нестабильной — именно так на сервер ставится эта бета до релиза).
