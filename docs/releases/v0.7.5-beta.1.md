# Xrayebator 0.7.5-beta.1 -- WARP, транспортная группа AWG 3.1, приватный каскад

**Дата:** 2026-11-13
**Предыдущий релиз:** `0.7.3` (2026-11-07)
**Xray-core:** `26.10.31` (без изменений)
**Статус:** бета. Для продакшена оставайтесь на `0.7.3`.

Это первый срез после разбора статьи «Методичка по построению VPN, осень 2026» и
сообщений о блокировках. Главное: у сервера появился выходной адрес, отличный от
входного, и AmneziaWG 3.1 начал выдавать полную транспортную группу вместо
половины.

## Что было не так

### 1. Трафик выходил с адреса входа

Статья называет это главной причиной блокировок: российские приложения узнают
внешний IP и сдают его, после чего адрес выжигают. У нас `sendThrough` в коде
отсутствовал вообще, а catch-all вёл в `direct` — то есть адрес выхода совпадал
с адресом, к которому подключаются клиенты.

### 2. «AWG 3.1» был включён наполовину

Режим назывался 3.1, но выдавались только `HeaderProtectionKey` и
`RandomTrailers`. По документации AmneziaWG транспортная защита 3.x — это ещё и
`ContentPaddingAddition` со рандомизацией таймеров. Без них повторяемые размеры
пакетов и постоянные интервалы остаются ровно тем, что анализирует поведенческий
DPI.

### 3. Одинаковая junk-тренировка у всех клиентов

`Jc`, `Jmin` и `Jmax` были серверными константами (5 / 10 / 50), то есть все
клиенты начинали сессию одинаково. Документация AmneziaWG называет это готовым
паттерном для DPI.

### 4. Дефект апгрейда 3.1

`_awg_ensure_31_params` выходил сразу, если `S3`, `S4` и `HeaderProtectionKey` уже
есть. Установка, прошедшая ранний 3.1-этап, навсегда оставалась без
транспортной группы — никакой путь её бы не обновил.

### 5. Страна сервера не определялась без quickstart

`_geo_detect_country` вызывался только из `quickstart` и `happ-setup`, а маркер
`/usr/local/etc/xray/.server_country` создаётся только там. Сервер, поставленный
обычным `install.sh` с профилями через CLI, маркера не имел никогда, поэтому
`inspect --json` отдавал пустые `country`/`city`/`flag` и десктоп показывал
сервер без флага страны.

### 6. Утечка в собственной правке

Первая версия WARP передавала приватный ключ в `jq` через `--arg`, то есть ключ
попадал в `/proc/<pid>/cmdline` (`0444`, читается любым пользователем). Это тот
же класс утечки, который закрывали в 0.7.3.

## Что изменилось

### Выходной адрес: Cloudflare WARP

Три команды, доступные и из CLI, и из десктопа.

```bash
sudo xrayebator warp-setup              # регистрация устройства, ключи 0600
sudo xrayebator warp-mode games-direct  # игры напрямую, остальное через WARP
sudo xrayebator warp-status             # JSON: configured / mode / applied
```

Три режима:

| Режим | Поведение |
|---|---|
| `all` | весь трафик через WARP |
| `games-direct` | `geosite:category-games` напрямую, остальное через WARP |
| `off` | catch-all возвращается в `direct` |

Почему WARP, а не второй IP у хостера: второй адрес обычно выдаётся в той же
подсети, поэтому блокировка первого уносит и второй — платить придётся снова.
WARP бесплатен, не требует второго сервера под шлюз и не требует второго IP.

Две детали, которые важны на практике: `reserved` (три байта из регистрации)
обязателен — без него WARP не отвечает; и `MTU` держится на 1280.

Честные ограничения, измеренные на живом хосте:

* пинг добавляет примерно 30-40 мс до целей вне сети Cloudflare;
* скорость остаётся в пределах 60-100 % от прямого пути в зависимости от
  контрагента и часа;
* WARP периодически недоступен десятки секунд и восстанавливается сам. Именно
  поэтому режим по умолчанию для игровых сценариев — `games-direct`, а не `all`.

### AmneziaWG 3.1: полная транспортная группа

Теперь выдаётся весь набор, а не только шифрование заголовка:

| Ключ | Что убирает |
|---|---|
| `HeaderProtectionKey` | открытые байты типа в заголовке |
| `RandomTrailers = on` | фиксированные длины handshake-пакетов |
| `ContentPaddingAddition` (2..10) | повторяющиеся размеры transport-пакетов |
| `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts` | постоянные интервалы сессии |

`Jc`, `Jmin` и `Jmax` стали клиентскими и уникальными на профиль: значения
выводятся детерминированно из имени профиля и его публичного ключа, поэтому
стабильны между вызовами и не требуют хранения состояния. `S1`-`S4`, `H1`-`H4` и
`HeaderProtectionKey` по-прежнему обязаны совпадать с сервером — их не трогали,
поэтому уже выданные `.conf` не ломаются.

### Приватный каскад (opt-in)

Команда `private-cascade render` генерирует отдельный конфиг для российской
входной ноды с зарубежным выходом: одни назначения идут локально, остальные
через разрешённый зарубежный узел. Живой конфиг не изменяется, результат
валидируется установленным ядром до записи. Развёртывание описано отдельно и
требует двух серверов.

### Десктоп

WARP появился в «Безопасность и TLS»: состояние, режим тремя кнопками, MTU и
endpoint. Десктоп вызывает ровно те же команды, что и SSH — своей логики
регистрации у него нет.

### Исправления

* Страна и флаг сервера определяются и без `quickstart`: при отсутствии маркера
  `inspect` делает сетевой запрос и не пишет файл, поэтому read-only контракт
  сохранён.
* Приватный ключ WARP передаётся в `jq` через окружение, а не аргументом.
* `test-ssh-protect.sh` больше не наследует `SSH_CONNECTION`/`SSH_CLIENT` живой
  сессии: раньше fallback-ветка сравнивала с адресом реального подключения, и на
  живом хосте проверка была молчаливо пустой.

## Проверено на живом сервере

Один хост, Ubuntu 22.04, Xray 26.11.9, AmneziaWG tools 3.1.

| Что | Результат |
|---|---|
| Подмена адреса выхода | вход и выход различаются, `warp=on` |
| Режим `games-direct` | применён, конфиг валиден, служба активна |
| `geosite:category-games` | существует (1063 домена); игровые домены идут напрямую, контрольные блокируются |
| Ключи AWG 3.1 | ядро приняло `content padding addition`, `rekey after time` и остальные и читает их обратно без искажений |
| Маршруты Xray | 6 транспортов + PQ, все HTTP 200, 171-310 мс |
| Hysteria 2 | реальный трафик через туннель, HTTP 200 |
| Полный `validation/` | **51/51** |
| Статус страны | `Germany` / `Frankfurt am Main` / флаг, маркер не создан |

Отдельно проверено, что каскад не трогает живой конфиг, а `warp-mode` делает
резервную копию и откатывается при отказе ядра.

## Обновление

```bash
sudo xrayebator-update dev
```

Обратная совместимость: серверные команды `--token` и `--aws-secret-access-key`
на месте, старый десктоп работает с новым сервером и наоборот. Миграций этот
релиз не добавляет, конфигурация сервера не меняется.

**Одна проверка после обновления**, если сервер ставился до этапа транспортной
группы:

```bash
sudo xrayebator awg-31 --on     # дозаполнит недостающие ключи
awg show awg0                   # должны появиться content padding addition и rekey
```

Если `awg show` показывает `random trailers: off` и не показывает padding,
значит на сервере работает бинарь менеджера старше этого релиза — обновите его и
повторите команду.

## Известные ограничения

* Режим `all` добавляет 30-40 мс; для интерактивных игр используйте `games-direct`.
* WARP — чужая инфраструктура: Cloudflare видит этот трафик, сервис бесплатный,
  но с лимитами, а регистрация может быть отклонена с интенсивно
  использованного адреса.
* Fail-closed для WARP ещё не реализован: при недоступном WARP трафик не утекает
  в `direct`, но и не работает.
* Приватный каскад требует двух серверов и Python 3 на входной ноде.

## Состав релиза

Работа над этим срезом шла в `dev`: приватный каскад, транспортная группа AWG,
уникальные junk-параметры, WARP с десктопной карточкой, исправление определения
страны и три исправленных теста.

Менеджер сервера и десктопное приложение публикуются из канонического
репозитория `howdeploy/Xrayebator`.
