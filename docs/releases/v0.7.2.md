# Xrayebator v0.7.2 — ядро Xray 26.10.31, защита от CVE-2026-98432 и перенос domainStrategy

> Обновление серверного менеджера и **Xrayebator Desktop GUI**. Ставится поверх `0.7.1` и любой `0.6.x` — миграции доделают всё сами. Нашли проблему или есть логи — пишите комментарием к релизу: по логам чиним быстрее всего.

## Изменения с 0.7.1

19 коммитов с тега `0.7.1`, из них 13 — этот цикл, остальные — документация предыдущего цикла (рекомендации по выбору VPS, домену и DNS и неделя наблюдений за стабильностью), которая до сих пор не входила в релиз.

Два независимых повода обновиться: **ядро Xray-core обновилось до 26.10.31** — это срочный security-релиз, — и **менеджер научился закрывать обе поверхности** уязвимости ядра Linux, которые ему подконтрольны.

- **`kernel-guard`** — новая команда (и пункт меню `16`): выключает MPTCP в ядре и дропает входящие IPv4-пакеты с IP-опциями. Защита от `CVE-2026-98432` — remote-root в ядре Linux, CVSS 9.8.
- **MPTCP выключен по умолчанию** миграцией `netguard_mptcp_2026`: ровно то же, что Xray-core сделала в листенере, но на уровне сервера — и для любого Go-сервиса, не только для Xray.
- **`freedom.domainStrategy` переехал в `sockopt`**: 26.10.31 объявила старое поле deprecated и «will be removed», а обновляется ядро само. Миграция `freedom_sockopt_2026` переносит значение на существующих серверах.
- **Правило `kernel-guard` больше не дублируется** — баг нашёлся на живом сервере при первом же включении.
- **Легаси-установщик закреплён на 26.10.31** (был 26.7.28 — ядро, которое ещё включает MPTCP в листенере).
- **Справочник рекомендаций** `docs/recommendations.md` (ru/en/zh): критерии выбора VPS без брендов и рефссылок, получение домена, Cloudflare и Route 53 по шагам, таблица «сколько ресурсов нужно» по реальным замерам.

## Если объяснить в двух словах

31 октября Xray-core выпустила **срочное** обновление: в ядре Linux нашли use-after-free в разборе IPv4-опций, и через MPTCP-листенер сервер получал root удалённо, без пароля. Go 1.24+ включает MPTCP по умолчанию — то есть его включал и Xray. В 26.10.31 Xray выключила MPTCP в листенере; мы в этом релизе глушим MPTCP ещё и в ядре, и дропаем IPv4-пакеты с опциями — тот самый код, где живёт баг.

Важно понимать границу: **это не замена обновлению ядра Linux.** Уязвимы все IPv4 TCP-листенеры (Xray, nginx, sshd), и настоящий фикс приходит только пакетом ядра. На 2 ноября 2026 у Ubuntu фиксы лежали в `-proposed` (jammy `5.15.0-203.213`, noble `6.8.0-149.149`), в `-updates` их ещё не было, так что `uname -r` стоит сверить с действующим advisory руками.

Вторая половина релиза техническая: новое ядро при каждом старте ругалось на наше же поле `freedom.domainStrategy` («deprecated and will be removed»). Ждать удаления нельзя — ядро обновляется командой `xrayebator update` без вашего участия, и после удаления поля домены начали бы резолвиться иначе (на IPv6-only сервере трафик просто встал бы). Перенесли значение в `streamSettings.sockopt`, старую форму пишем только в миграции.

## Что нового

### 1. `kernel-guard` — защита ядра от CVE-2026-98432

```bash
sudo xrayebator kernel-guard --status    # факты в JSON
sudo xrayebator kernel-guard --enable    # MPTCP off + дроп IPv4-пакетов с IP-опциями
sudo xrayebator kernel-guard --disable   # снять оба изменения
```

Что делает `--enable`:

1. **MPTCP выключен в ядре** — `net.mptcp.enabled = 0` в `/etc/sysctl.d/99-xrayebator-netguard.conf`. Ничего в стеке MPTCP не использует: VLESS/Reality это TCP, Hysteria 2 и AmneziaWG — UDP.
2. **Дроп входящих IPv4 TCP-пакетов с IP-опциями** (`IHL > 5`) — правило дословно из рекомендации Ubuntu Security Team, в отдельной nft-таблице `cve_2026_98432` с приоритетом `-310` (раньше filter-хука UFW) и своим юнитом автозагрузки `xrayebator-netguard.service`.

Почему своя таблица, а не `nftables.service`: стандартный `/etc/nftables.conf` на Debian/Ubuntu начинается с `flush ruleset`, и его включение при загрузке снесло бы весь набор правил UFW. Наш юнит грузит только свою таблицу и не делает `flush` ни при старте, ни при остановке.

`--status` отдаёт: запущенное ядро, `newer_kernel_installed` (ядро новее уже установлено, но не загружено), `reboot_required`, `mptcp_supported`/`mptcp_enabled`, `ipv4_options_drop`, версию Xray-core и `xray_mptcp_safe` (≥ `26.10.31`). Захардкоженной таблицы «в какой версии ядра починили» нет намеренно: она устаревает быстрее, чем помогает.

Если в системе нет `nft` (бывает на минимальных образах: UFW есть, пакета `nftables` нет), команда выключит MPTCP и честно ответит `partial: true` — поставьте пакет и повторите, она идемпотентна.

### 2. MPTCP выключен по умолчанию

На уже развёрнутых серверах `net.mptcp.enabled = 0` применяет миграция `netguard_mptcp_2026` при первом запуске меню, `quickstart` или `happ-setup`. Она не меняет `config.json`, поэтому возвращает «no-op» и **не перезапускает ядро Xray** — перезапуск здесь был бы регрессом, а не осторожностью.

Дроп IPv4-опций при этом остаётся осознанным решением оператора: он меняет то, какие пакеты сервер принимает вообще.

## Что исправлено

### 1. `freedom.domainStrategy` → `streamSettings.sockopt.domainStrategy`

26.10.31 при каждом старте печатает:

```
The "freedom.domainStrategy" setting is deprecated and will be removed.
For compatibility, its value has been automatically migrated to "sockopt.domainStrategy".
```

На 26.3.27 (то, что стояло на продакшене) предупреждения нет — значит поведение изменилось именно в этом обновлении. `install.sh` теперь пишет новую форму сразу, а миграция `freedom_sockopt_2026` переносит значение на существующих серверах и удаляет legacy-ключ. Уже заданный `sockopt` не перетирается; если legacy-поля нет, миграция молчит и ядро не трогает.

### 2. Правило `kernel-guard` дублировалось при активации юнита

Живая находка на свежей установке: после `kernel-guard --enable` в nft-цепочке оказывались **два одинаковых правила** дропа. Причина: `nft -f` файла с `table inet X { ... }` не заменяет таблицу, а дописывает правило в неё, а `systemctl enable --now` запускает юнит, который грузит тот же файл второй раз. Второй дроп безвреден (первый уже отсёк пакет), но цепочка росла бы с каждой активацией.

Теперь `ExecStartPre`/`ExecReload` сначала удаляют нашу таблицу (`-nft delete table inet cve_2026_98432`), и валидация требует эту строку. Проверено живьём: три включения подряд дают ровно одно правило, после перезагрузки — тоже одно.

### 3. Легаси-установщик ставил уязвимое ядро

`gui-legacy` (архивный PySide6-интерфейс) разворачивает **серверное** ядро из закреплённой версии и ставил `v26.7.28` — то есть ядро, которое ещё включает MPTCP в `DefaultListener`. Версия поднята до `26.10.31`, SHA-256 обоих ассетов сверены и с `.dgst` из релиза, и с реально скачанными файлами.

## Чем это не является

- **Не обновление ядра Linux.** Дроп IPv4-опций сокращает поверхность атаки, но не заменяет патч. Пакет ядра ставится штатно через `apt`, после установки нужна перезагрузка.
- **Не «полностью безопасно».** Правило Ubuntu снимает самый простой путь эксплуатации; сам race в TCP-обработке остаётся в ядре, пока оно не обновлено.
- **Не GUI-функция.** `kernel-guard` живёт в CLI и в меню (пункт 16), как и Telegram-алерты: в десктоп-приложении этой карточки нет.
- **Не закрепление версии ядра Xray.** Менеджер по-прежнему ставит latest из GitHub Releases; вам не нужно выбирать `26.10.31` руками — достаточно, чтобы на сервере оказалась версия не ниже (проверить: `xrayebator kernel-guard --status` → `xray_mptcp_safe`).

## Важно перед обновлением

### Требования к серверу

Без изменений: Debian 12/13 или Ubuntu 22.04/24.04, `bash`, `root`/`sudo`, `systemd`, `apt`. Для дропа IPv4-опций нужен `nft` (пакет `nftables`; если его нет, `--enable` скажет об этом и включит только MPTCP).

### Что стоит знать

- **Break changes нет.** Порты, профили, подписки и пароли `Hysteria 2`/`AmneziaWG` не меняются.
- **После обновления ядро Xray перезапустится один раз** (как обычно при `xrayebator update`) — активные клиенты переподключатся сами.
- **Защиту ядра на существующем сервере, скорее всего, надо включить руками:** MPTCP выключится миграцией, а дроп IPv4-опций — командой `sudo xrayebator kernel-guard --enable` или пунктом меню `16`.
- **`--route` у `sni-change`/`fp-change`/`port-change` — это номер маршрута с нуля**, не метка. У профиля с несколькими маршрутами без него команда откажет с подсказкой.
- Если вы обновляете сервер с ветки `dev` командой `xrayebator update`, ветка останется `dev`; для стабильной — `xrayebator update main`.

## Как обновиться

### Сервер

```bash
sudo xrayebator-update          # полный жизненный цикл проекта
# или только менеджер + ядро Xray-core:
sudo xrayebator update
# и один раз включить защиту ядра, если нужна:
sudo xrayebator kernel-guard --enable
```

### Xrayebator Desktop GUI

Скачайте установщик из ассетов релиза и поставьте поверх — данные и настройки серверов сохраняются.

## Сборка

Собирается тем же workflow: Ubuntu (AppImage), macOS arm64 (dmg + zip), Windows (exe). Перед сборкой прогоняются typecheck, unit-тесты и все 47 Bash-валидаций.
